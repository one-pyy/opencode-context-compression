# 删除许可与有效信息提炼

## 文档定位

本文档是 delete 行为的唯一语义入口；定义删除许可、有效信息保留、输入选择与本地落盘职责。

## 实施状态

删除准入、混合输入、独立 delete prompt 与既有 result group / projection 链路已实现并通过确定性回归测试。真实模型质量验收尚未通过：已观察到有效要求遗漏与证据限定丢失，待修订和复测；执行入口见 [修订执行文件](../../tmp/todo/2026-09-15_delete-effective-information.md)。

现有实现将短用户消息分类为 protected，但 delete 输出跳过 compact 的 opaque 校验，并生成整段结果。该分类不能作为 delete 保留用户原文的保证；用户信息保留需要按目标契约单独验收。

## 基本定义

`allowDelete` 是当前运行时是否允许创建 delete 型 mark 的准入条件。

准入通过后，历史重放使用已接受的动作与结果组；该配置不作为 mark / replacement 的长期业务字段。

## 用户授权

delete 仅用于用户明确要求使用 `context-retire` skill 的本次整理任务。主 agent 加载 skill 后，按用户范围完成文件留存、核对与选区；授权不延续到后续独立任务。普通上下文提醒与通用 cpmark 请求使用 compact。

`allowDelete` 是运行时能力开关，不代表用户已经授权本次 delete。用户授权由 skill、工具描述与 reminder 的行为规则约束，当前 API 不验证自然语言授权。skill 资产与部署入口见 [手工整理 Skill](../config/prompt-assets.md#手工整理-skill)。

## 共同规则

- compact 与 delete 共用 mark → 模型处理 → result group → projection 链路。
- compact 保留历史摘要；delete 让旧过程退出模型输入，只继承后续仍然有效的信息。
- 宿主原始历史保持不变。删除只改变模型可见投影，不删除本地项目材料或宿主档案。
- 系统消息保持保护；本契约也不改变每轮重新注入的系统指令、工具规则与项目规则。

## Admission 规则

- `mode=compact`：总是允许创建 mark
- `mode=delete`：只有当前 `allowDelete=true` 时才允许
- 若不允许 delete，则该次 tool 调用返回错误结果，不生成可重放的 delete mark

## 目标与保留标准

首要目标是减少旧任务、旧命令和探索过程对后续决策的干扰，token 节省是次要收益，不要求 delete 输出一定比 compact 更短。范围选择依据内容是否仍参与当前判断及其有效信息是否已安置，消息年龄、条数或任务完成标签均不能独自证明可删除。自动调度条件见 [压缩生命周期](compaction-lifecycle.md#触发条件)。

delete 可以移除范围内用户消息的原文，包括短用户消息，前提是有效信息得到保留：

- 当前仍适用的用户要求、约束、明确决定与偏好，保留适用范围和来源身份。
- 相关完成结论、验证结果及其限制，仍未解决的问题与继续工作所需信息。
- 影响后续选择的必要依据，以及本地资料的可定位入口。

助手建议不能升级为用户授权；单次要求不能扩大为长期偏好。只有明确替代或失效的要求才能退出有效状态；存在歧义时保留未决含义及必要原文，交由主 agent 核查，不由 delete 模型选定解释。已压缩输入缺失的事实不能凭推断补全。

## 输入选择

delete 覆盖多个范围时，按来源顺序组合已有 compact 结果与尚未覆盖的原文。使用范围内有效的已应用结果，排除被覆盖的旧结果；同一来源只进入一次，不同时加入摘要及其背后的原文。结果存在但尚未应用时，仍以当前有效表示为准。

compact → delete 允许二次提炼。普通 compact 保持已有 compact 结果不变。delete 结果再次作为模型输入的行为尚未定义，不能从 compact → delete 推导其处理规则。

输入从结构化结果组及原始范围组装，不从最终投影文本反向清洗。每个摘要片段保持原始来源范围与身份线索，未覆盖用户消息的正文进入提炼判断；不得只传 opaque 占位符使模型无法判断用户要求。插件生成的 reminder、删除提示、可见编号包装不作为待提炼事实。

选择范围必须完整覆盖要消费的摘要片段；若只覆盖片段的一部分，主 agent 应先调整为包含完整片段的合法范围，或回查原文后重新选区。不能按原始消息比例切割摘要，也不能把范围外的摘要事实当成范围内内容删除。

输入大小按实际组装内容检查，不能用被摘要替代的整段原文体积代替。若仍超出模型可用输入预算，保留尚未处理的内容，由主 agent 拆成可独立处理的合法范围；不得静默截断整个输入或因超限恢复为更大的全量历史。工具字段的显式截断沿用 [文本渲染契约](model-visible-transcript.md#json-与截断规则已实现)，有省略的证据不能视为完整事实。

默认 direct LLM transport 在发送 delete 请求前检查实际 system prompt 与用户输入的估算 token。预算来自 OpenCode provider 对应模型的 `limit.input`，否则使用 `limit.context - limit.output`；元数据不足时由服务端容量校验兜底。计数服务不可用时使用 UTF-8 字节数保守估计。这不是各 provider 精确 tokenizer 与消息封装开销的保证；服务端拒绝仍按模型失败处理，不提交结果。自定义 transport 需自行遵守相同的超限保留契约。

## 输出与替换

输出是后续有效信息的合并结果，不是旧任务的过程复述。仍适用的信息保留在结果中，或引用已经核对的本地权威材料；会直接约束下一步行动的要求应保留必要内容，不能只留一个无人知道何时读取的路径。

无有效信息需要继承时可输出极简删除提示；有有效信息时必须保留，不能为满足“删除”名称而强制清空。输出沿用现有 JSON envelope，只有 `compression_output` 进入结果组，详见 [Prompt 硬约束](../config/prompt-assets.md#硬约束)。

只有完整、通过校验的结果组才能接管来源范围；模型调用、校验或持久化失败时保留既有可用表示。delete 生效后来源范围不可通过 `compression_recall` 取回，所需资料通过已核对的本地文件取得；来源定位仍用于覆盖判断。拒绝范围及生效规则见 [Recall 删除边界](recall-tool-contract.md#删除边界)。

## 主 agent 与本地文档职责

主 agent 负责选区、判断当前有效性，并在请求 delete 前完成需要的落盘与核对。正式需求和约定进入项目 Docs，可复用经验进入 knowledge_database，临时进度和未决判断按项目临时材料规则保存；临时假设不能写成正式约定。

落盘完成意味着内容与来源已核对且后续能找到，不只是文件存在。仍有效的要求、偏好、结论、证据限制及未决工作必须先完成文件留存；直接约束后续行动的必要信息同时保留在整理结果中。仍依赖未完成落盘或原文判断的范围暂不删除。

delete 模型只处理提供的输入，不负责写项目文件，也不假定自己已读取引用文件或已验证落盘。必要的有效性上下文由主 agent 提供；无法判定的内容保留或回查，而不是猜测它已经过期。
