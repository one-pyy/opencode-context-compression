# 整理并退役旧会话

将旧会话整理为当前有效的最终版信息，先写入可找到的本地文件，再通过 `compression_mark` 的 delete 模式让不再用于后续工作的旧过程退出上下文。目标是减少过时指令和过程对后续工作的干扰，token 节省不是首要指标。

delete 用有效信息的合并结果替换旧过程。范围内仍有有效要求、决定、结论或未决事项时也可退役，前提是必要信息已留存并核对，后续不再依赖旧过程的细节；通过 hint 指定必须继承的关键内容。

本 skill 由主会话助手执行：负责文件留存、有效性判断、自主选区及工具调用。后台 delete 模型负责整理替换内容，不负责写文件或选择范围。如之前未加载本 skill，请先加载；已完整加载则直接复用。

## 输入与能力

输入是用户整理要求或上下文提醒、当前可见会话及相关项目文件。用户指定范围时按该范围处理；提醒触发的自动流程以已应用 compact 摘要为候选，可以包含中间符合条件的原文，独立未压缩范围使用 compact。先检查已完成任务的摘要及先前未处理的残余；条数、年龄和 token 压力只用于定位，是否退役取决于内容是否仍用于后续工作。

执行前确认当前插件允许 delete。工具不可用、能力未开启或有效信息无法核对时，保留受影响内容并说明阻塞，不自行开启配置。主助手按下述标准自主选择并执行退役：保留后续仍需要的信息，退役已失效、被替代或不再需要的旧过程；无法判断是否仍有用时保留。

## 工作流程

1. 梳理候选范围的最终版本：区分用户要求、偏好、已确认决定、实现事实、验证限制和未决事项。后续修改只覆盖真正冲突的旧条款，其余独立要求继续有效。助手建议不得变成用户决定。
2. 核对已有文件，把仍有效的信息补入合适位置：正式契约进入项目文档，可复用判断进入知识库，临时进度和未决信息进入项目临时记录。复用项目既定目录；没有约定时明确记录文件位置和用途。不要把未决设计写成已批准契约。
3. 对照会话与文件检查完整性，包括精确值、适用范围、用户非目标、证据限制、尚未完成的工作及恢复入口。后续模型默认只看到整理结果，详细资料靠读文件取得；delete 生效后无法通过 `compression_recall` 取回覆盖范围。文件存在不代表内容完整，必须读取或检查本次差异。
4. 先取候选跨度的条目：优先复用 reminder 附带的 delete 模式 inspect 清单，它只覆盖该 reminder 的 anchor 跨度。清单缺失、是 compact 模式或不足以覆盖候选时，调用 `compression_inspect` 并设置 `mode="delete"`，`to` 取需要检查的最新可见消息。返回按位置排列的 `entries`：`kind=fragment` 是已应用 compact 摘要片段，`kind=user` 用于核对 protected 用户消息，`kind=compressible` 是未压缩范围，独立处理时使用 compact，也可作为合法退役范围中的混合输入。清单只描述可选结构，是否退役仍按内容用途判断。完整覆盖每个所选摘要片段：直接用 `kind=fragment` 的 `from` / `to` 标记对，或用包住整个片段的宿主 visible id；片段标记须唯一匹配当前结果，并核对第 5 步的标记包含限制。夹在范围内的用户消息与原文也必须核对并保留有效信息。条目 token 估算当前实际可见文本的大小：fragment 为摘要、user 为用户正文、compressible 为当前未压缩文本；总数是这些条目的合计。使用摘要与未覆盖原文，不展开全部旧历史。成功的待处理 mark 视为已处理。仍依赖原文判断、材料不完整或含当前活跃争议的范围保留。
5. 按任务或主题核对候选的退役依据、有效信息落点及保留范围。建议跨 inspect 统计条目选择符合条件的连续范围，减少调用往返；可覆盖多个已应用 compact 摘要及中间符合条件的用户消息与原文。delete 必须完整覆盖涉及的已有 compact 标记及摘要片段，不能严格落在已有 mark 内部；避开已有 delete 和成功的待处理标记，按 compression_mark 工具说明核对区间关系。没有符合条件的候选时继续当前任务。
6. 对符合标准的范围调用 `compression_mark`，设置 `mode="delete"`。在 hint 中明确指定必须继承的当前有效事实、精确约束、证据限制、未决事项、完整文件路径及用途，并说明哪些旧内容已被最终版本替代。关键保留项须进入最终替换正文，不能只留在模型的计划字段；hint 不代替事实核对。多个独立合法范围在同一轮标记，避免相互重叠；活跃内容、区间冲突或输入超限需要时才拆分，不截断有效信息。
7. 汇报实际完成的文件留存、已接受的标记范围及未处理原因。mark 成功只表示请求已接受，不代表模型处理或替换已完成。随后回到用户任务。
