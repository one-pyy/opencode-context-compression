# 整理并退役旧会话

将用户指定的旧会话整理为当前有效的最终版信息，先写入可找到的本地文件，再通过 `compression_mark` 的 delete 模式让旧过程退出上下文。目标是减少过时指令和过程对后续工作的干扰，token 节省不是首要指标。

本 skill 由主会话助手执行：负责文件留存、选区、征求用户确认及工具调用。后台 delete 模型负责整理替换内容，不负责写文件或决定用户授权。

## 输入与授权

输入是用户本次整理要求、当前可见会话及相关项目文件。授权仅覆盖本次整理任务及用户指定范围，完成后不延续为后续任务的 delete 许可。用户未指定范围时，先从久远且已完成的任务中选取候选，优先检查已 compact 的历史及先前未处理的残余；条数和年龄只用于定位，不能证明信息已失效。

调用前确认用户明确要求使用本 skill，且当前插件允许 delete。缺少授权、工具不可用或文件无法核对时，停止 delete 并说明阻塞；不要自行开启配置。

## 工作流程

1. 梳理候选范围的最终版本：区分用户要求、偏好、已确认决定、实现事实、验证限制和未决事项。后续修改只覆盖真正冲突的旧条款，其余独立要求继续有效。助手建议不得变成用户决定。
2. 核对已有文件，把仍有效的信息补入合适位置：正式契约进入项目文档，可复用判断进入知识库，临时进度和未决信息进入项目临时记录。复用项目既定目录；没有约定时明确记录文件位置和用途。不要把未决设计写成已批准契约。
3. 对照会话与文件检查完整性，包括精确值、适用范围、用户非目标、证据限制、尚未完成的工作及恢复入口。后续模型默认只看到整理结果，详细资料靠读文件取得；delete 生效后无法通过 `compression_recall` 取回覆盖范围。文件存在不代表内容完整，必须读取或检查本次差异。
4. 先取候选跨度的 token 计数：调用 `compression_inspect`，`to` 取当前最新可见消息，覆盖整段候选跨度。sections 与 atoms 是计数辅助，不构成自动可删建议，是否删除仍由任务语义决定；reminder 附带的清单只覆盖该 reminder 的 anchor 跨度，不能替代这一步。然后选择连续的合法范围。覆盖已有 compact 摘要时包含整个摘要片段：片段在投影里以 `[referable_...~referable_...]` 区间呈现，这两个区间标记可直接作为选区端点（须唯一匹配当前结果组的片段标记），也可以用包住整个片段的宿主 visible id（片段前后最近的可见消息）选区，两者都必须完整覆盖片段。使用摘要与未覆盖原文，不展开全部旧历史。暂不处理已有 delete 结果；成功的待处理 mark 视为已处理。仍依赖原文判断、材料不完整或含当前活跃争议的范围保留。
5. 向用户提交选区建议并等待确认。按任务或主题说明哪些范围已满足删除条件、其中建议删除哪些；每项写清范围所含内容、可删依据、建议理由及有效信息的文件落点，并说明暂不可删的范围与阻塞原因。提醒用户 delete 生效后无法 recall。用 `question` 工具让用户选择本次实际删除的范围；工具不可用时直接询问并等待回复。调用本 skill 不等于确认全部候选；未经选区确认不调用 delete，后续扩大范围须重新确认。
6. 仅对用户确认的范围调用 `compression_mark`，设置 `mode="delete"`。在 hint 中给出当前有效事实、精确约束、未决事项、已核对文件及其用途，并说明哪些旧内容已被最终版本替代。多段分别标记，范围不重叠；输入超限时在已确认范围内按独立任务拆分，不扩大范围或截断有效信息。
7. 汇报实际完成的文件留存、已接受的标记范围及未处理原因。mark 成功只表示请求已接受，不代表模型处理或替换已完成。随后回到用户任务。
